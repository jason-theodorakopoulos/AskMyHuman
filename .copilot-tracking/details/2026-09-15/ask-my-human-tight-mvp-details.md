## Delivery Model

Implementation uses a contract-first fan-out and single-owner integration model.
Each parallel workstream owns disjoint product and test files. Shared manifests,
composition roots, root fixtures, generated locks, CI, and documentation retain a
single owner.

Rules for all workstreams:

* Branch from the completed Phase 0 foundation commit.
* Do not edit files assigned to another workstream.
* Request dependency changes from the foundation owner; do not independently edit `pyproject.toml` or `uv.lock`.
* Keep test fixtures under the owning test directory unless two workstreams need the same behavior.
* Do not place service construction in feature modules; export factories and implementations for the application integrator.
* Do not weaken the one-call, one-human, one-turn, one-container, and one-database MVP limits.
* Rebase workstream branches onto the foundation before handing them to the application or infrastructure integrator.

### Phase-Specific Ownership And Handoffs

| Surface | Initial owner | Handoff | Final owner |
|---|---|---|---|
| `pyproject.toml`, `uv.lock`, `.python-version`, settings, contracts, schemas, domain, ports, and fakes | Foundation owner | No handoff; dependency and contract changes return to this owner | Foundation owner |
| `tests/conftest.py` | Foundation owner | After Phase 0 validation | Application integrator |
| `infra/main.bicep` and `infra/environments/dev.bicepparam` | Infrastructure integrator | No handoff; this owner freezes and later composes module contracts | Infrastructure integrator |
| `src/ask_my_human/main.py` and `tests/integration/test_asgi_app.py` | Application integrator | Created only after Phase 1A workstreams pass | Application integrator |
| Bicep module files | Assigned module owners | After independent module build | Infrastructure integrator for composition only; module owner retains file edits |
| `Dockerfile`, `.dockerignore`, `compose.yaml`, CI, `tests/e2e/test_live_call.py`, README.md, and conditional `.gitignore` edits | Release owner | Created or edited after integration | Release owner |

Only one listed owner may edit a surface at a time. The Phase 0 application
foundation and Bicep contract freeze are coordinated sequentially even though
they have different named owners.

### Step 0.3: Freeze Domain State And Application Ports

Implement framework-free domain models and the pending-to-terminal transition
rules. Define narrow async ports for the inbound `AskHumanUseCase`, request
repository, ACS gateway, clock, and telemetry. Add deterministic fakes used by
all application and adapter tests.

The repository port must expose `create_or_replay`, `attach_call_id`, `get`,
`complete_if_pending`, `expire_stale`, and `purge_terminal`. The call gateway must
expose `create_call`, `start_recognition`, `acknowledge_and_hang_up`, and
`hang_up`. The clock supports `now` and `sleep`. Telemetry accepts only typed,
content-free fields.

The inbound `AskHumanUseCase` protocol exposes `ask` and `handle_call_event`
using only domain and public contract types. HTTP and MCP adapters type-check
against this protocol and its fake while the core workstream implements the
concrete `AskHumanService` concurrently.

Files:

* src/ask_my_human/domain/models.py - Internal request, state, outcome, callback, and principal models
* src/ask_my_human/domain/transitions.py - Valid terminal transitions and first-result semantics
* src/ask_my_human/application/ports.py - Repository, call gateway, clock, and telemetry protocols
* tests/support/__init__.py - Shared test support package marker
* tests/support/fakes.py - Deterministic fake use case and outbound port implementations
* tests/unit/domain/test_transitions.py - Complete transition matrix

* Fakes support deadline advancement, callback races, cancellation, and idempotent replay without network access.
* HTTP and MCP adapters can type-check and test against the fake `AskHumanUseCase` before the concrete service merges.
